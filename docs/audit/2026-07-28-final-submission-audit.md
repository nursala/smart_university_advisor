## Discrepancies found

1. **Wrong-repo risk in the audit brief itself.** The brief's Ground Truth and entire verification plan describe files that don't exist in the session's stated primary working directory (`smart-univercity-advisor-ai`, a Flask/Python project) and do exist in a separate sibling repo (`smart_university_advisor`, the actual Drogon C++ project). This audit targeted the latter. Flagging prominently since silently guessing wrong here would have invalidated the entire report.

2. **`cpp-project-summary.md` does not exist.** Neither in the working tree nor anywhere in `git log --all --follow` for that path. The brief's Ground Truth D treats it as a currently-present "older running log" with specific stale claims ("no auth system exists at all", "EnrollmentsController has raw SQL with no transactions", "12 endpoints"). None of these claims could be checked against a live file because the file itself is not there — whatever its history, it is not part of the current repo state and should not be relied on by the team.

3. **`docs/auth-tests.md` "17 test cases, 44 assertions" is stale.** Live run inside the container: **34 test cases, 199 assertions, 0 failures.** All tests pass — this is not a regression, just an out-of-date count in the doc (the suite clearly grew after this doc was last touched).

4. **`services/PasswordHasher.h`'s code comment is stale.** It warns that `database/seed.sql` contains "decorative" bcrypt-shaped hashes that "will NOT verify" and that seeded accounts need a real password via registration or a reseed. Live-verified: `database/seed.sql` already contains real `pbkdf2_sha256$210000$...` hashes, and both README-documented demo accounts (`adam@example.com`/`DemoStudent2026!`, `admin@example.com`/`DemoStaff2026!`) log in successfully today. The comment describes a past state that has since been fixed; leaving it in place risks a future contributor "fixing" something that isn't broken.

5. **`localhost:5433` is not usable from the host with the documented credentials in this environment**, despite `docker exec`-level and container-to-container access working fine with the identical `advisor`/`advisor_password` pair (see status-table row 0.3). The README states flatly that "PostgreSQL is available to local tools at `localhost:5433`" with no caveat; in this sandbox that claim did not hold up under an actual host-side connection attempt.

6. **README's "Architecture" section header text doesn't literally match what's on disk.** README states `Controller -> Service -> Repository -> PostgreSQL`, but no `repositories/` directory or Repository-layer classes exist anywhere in the repo — every service (`StudentService`, `CourseService`, `EnrollmentService`, `UserService`) talks to `drogon::orm::DbClientPtr` directly. This is the same Route→Service collapse the audit brief's Ground Truth B anticipated, but the README's own wording overstates the layering by naming a "Repository" step that isn't actually a separate class/file anywhere in the codebase — worth a wording fix so the README doesn't claim a layer that doesn't exist.

7. **Two controllers still contain one raw `execSqlAsync` SELECT each, bypassing the service layer** (`EnrollmentsController.cc:156-157`, `StudentsController.cc:177-178`) — both simple ownership/existence pre-checks, not full business logic, but a literal violation of "controllers only route/validate/shape" that the 07-22 fix-batch plan did not cover (its stated scope was the `create` path and the general int64-overflow sites, not these two `remove`/`riskAnalysis` pre-checks).

8. **GPA values leak binary floating-point noise into API responses** (e.g. `"current_gpa":87.400000000000006` instead of `87.4`), observed live on both `PATCH /enrollments/{id}/grade` and `GET /students/{id}/profile` after a grade was recorded — reproducible, not a one-off. `EnrollmentService.cc` does apply `std::round(x * 100.0) / 100.0` before building the JSON response, but the resulting `double` still isn't representable exactly in binary and jsoncpp appears to serialize it at full double precision rather than to 2 decimal places. This wasn't something the audit brief asked about specifically, but it's a real, easily-reproduced correctness/presentation defect the team should know about before submission, since a grader poking at the API by hand will see it immediately.
